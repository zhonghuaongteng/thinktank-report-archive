# 每周首页编选输入

首页承担编辑导读与阅读导航。先核准各篇研究内容，再编写当期首页；不得用收录数量或标签分布自动推断研究态势。

## 保存位置

默认路径为 `briefs/weekly/<年份>/<业务日期>_editorial.json`。日期须与本轮固定业务日期一致。该文件与当期资料一起保存、提交，内容更改后重新渲染并检查，不能沿用旧首页。

以下仅说明结构，日期、网址、观点和复核记录都须用当期已核准内容填写。示例中的 `review.completed` 为 false；只有实际完成内容复核后才设为 true，不能把示例状态当作已核验。

```json
{
  "date": "YYYY-MM-DD",
  "headline": "用一个明确的问题或有依据的发现组织本期阅读",
  "lead": "简洁的编辑导读，说明研究对象、联系和分歧；依据不足时只提出阅读线索。",
  "discoveries": [
    {
      "title": "一处值得细读的发现",
      "text": "具体内容、关键比较或方法，以及值得继续阅读的原因。",
      "source_url": "https://example.org/original-report",
      "source_locator": "原报告第X页、图Y或具体章节",
      "article_url": "https://example.org/current-week-report",
      "metric": "可选：一个准确的数值或短标签",
      "metric_label": "若有数值：年份、分母、单位与适用范围"
    }
  ],
  "connections": [
    {
      "title": "本期实际相关的持续研究问题",
      "text": "说清这篇研究提供了什么入口，不强贴企业基础研究、AI4S或区块链标签。",
      "article_urls": ["https://example.org/current-week-report"]
    }
  ],
  "review": {
    "completed": false,
    "note": "完成核验后记录原文位置、数字口径、编辑推演与来源边界。"
  }
}
```

`metric` / `metric_label` 可整体省略；没有合适数字时直接用具体发现，不造数字。通常选择两三项发现，但按当期资料判断，不设置硬配额。研究连接也只保留真实相关的问题；`connections` 可为 `[]`，无需为没有关联填一段解释。

`source_url` 是支持该发现的原报告或其引用的原始研究；`article_url` 是本期可进入深读的重点篇章来源链接。两者可以不同，但须在 `source_locator` 和复核记录中交代关系，不将旧的原始研究当作本周新发布。

有必要呈现图表或制度比较时，可增加 `data_markdown`，使用安全 Markdown 编写小标题、表格或工作区内图片，并就近注明来源、页码、数据口径和适用使用依据。只接收可核查的图表，不在首页添加装饰图填白；图表也不能顶替每篇真实漫画。

完整导航由本期重点篇章生成，不在JSON另写一套可能失效的标题和页码。首页保留精选发现的篇章入口；完整目录可按篇幅放在正文末尾自然续排，并从首页提供锚链接，避免又制造独立的半空目录页。未核验真实PDF页码时使用篇章锚点，禁止按每篇两页计算。

## 编辑与交付检查

- 核实编选日期与本轮业务日期一致、发现和研究连接指向当期实际重点条目、来源及位置可核查。
- 首页主线与事实分开：允许编辑提出问题，不把同向案例写成共同机构立场，也不据本周几篇材料直接宣称长期趋势。
- 内容少时保留简洁有效的导读；内容多时精炼入口、将次要导航自然移到后页，不裁文、不缩字号、不固定四页开场。
- 渲染后检查第1页及导航是否可读、完整、均衡，检查图表、链接和统计口径，并将结果记入当期运行回执。
- 程序校验只证明输入格式、引用归属和渲染一致性；`review`是本轮编辑核验记录，不代替实际原文与PDF阅读，也不要求用户重复批准已有授权。
- 非空重点周次缺少已复核首页时，初步渲染可以显示真实条目导览，正式投递仍须补齐首页。零重点周次如实呈现，不编造发现。
