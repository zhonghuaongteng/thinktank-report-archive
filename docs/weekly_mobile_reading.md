# 周报手机阅读版

依据2026-10-18至19日及2026-11-16日用户要求，后续重点、简讯、标题和漫画均用普通读者能理解的表达。每周同时提供手机阅读版和独立设计的PC漫画版，在原授权的一封邮件中附上两版各自的PDF与HTML，共四个附件；发送对象和每期发送次数不变。PC漫画版执行 [周报PC漫画阅读版](weekly_comic_reading.md)。本次修改适用于后续周次，不重制或重发2026-11-15期及其他已发送版本。

## 双版本内容与投递

两版以同一份当期核准正文和简讯为输入，沿用同一业务日期、七日窗口、原文证据和选材结果。先完整写清报告观点、事件前因后果、具体做法、关键证据与有信息量的案例，再分别设计漫画；不因制作第二版重新采集、另选材料或删减正文。两版均须保留全部重点正文、简讯、机构、日期与来源链接。

读者端去掉例行防御表述、编选边界说明和制作核查过程，例如“仅供参考”“不构成……”“本篇只是……”“相比漫画增加……”等。选编范围、阅读页段、证据充分性判断和复核过程放入内部编选记录。影响事实理解的时间、样本、分母、提案或实施状态仍在相应叙述中具体讲清；不把建议写成实施结果，也不把必要事实条件改成页末免责声明。

手机漫画继续采用适合窄屏的独立竖版分镜，文字简洁、字号清楚，围绕人物动作、物件与具体问题组织。手机与PC漫画分别编写分镜和提示词、分别生成；不能将同一幅图换文件名、裁切、缩放或重新导出后算作另一版。两版可共享核准事实、术语和视觉风格，但PC版须有独立的场景展开、案例或证据表达，不能只是手机短句的放大版。

后续每期文件名和投递清单固定区分版本，`<D>` 为同一北京时间业务日期：

- `briefs/weekly/<年份>/<D>_手机版/<D>_国际科技智库周报_手机版.pdf`
- `briefs/weekly/<年份>/<D>_手机版/<D>_国际科技智库周报_手机版.html`
- `briefs/weekly/<年份>/<D>_漫画版/<D>_国际科技智库周报_漫画版.pdf`
- `briefs/weekly/<年份>/<D>_漫画版/<D>_国际科技智库周报_漫画版.html`

两份HTML均内嵌本版所用图片，作为单个附件打开时能显示完整正文和漫画，不依赖本机路径、旁置图片目录或登录后的临时图片地址。正文原文链接可指向外站。邮件发送前核对四个附件的版本、日期、文件大小及验收哈希，并检查总附件大小符合所连接邮件服务的限制；需要优化图片时重新验收清晰度和页面。邮件发送后核对同一期SENT记录及四个附件，不另发第二封来补齐缺失版本。

## 已验收版式

本期模板为92×164毫米窄竖页，左右边距6毫米，正文12.2点、1.58倍行距，单栏。按390像素屏宽显示时，正文约18.2像素。小标题14点，文章标题16点，来源10点。图片为独立竖版漫画，上下分镜、少字大字，禁止把横版整图直接缩小后当作手机适配完成。

首页简短导读；第二个阅读入口列重点目录，简讯目录紧邻简讯。提供整期目录、逐篇书签、文内跳转和原文链接。页码和书签必须读取实际PDF分页后生成，不按模板估算。正文自然续页；每则简讯从新页开始，本期23则各一页，但不以缩字或删内容强求以后全部一页。

简讯先说明具体问题和新变化，再解释做法、数字和必要状态；可分两三个自然段，不强套“背景—机制—意义”栏目。保留机构、日期和原文链接。摘要、术语、统计口径及状态应能通过大字正文理解，不能要求读者放大漫画查找关键条件。

## 渲染输入与执行

先完成当期核准的阅读HTML；手机渲染不抓取、不改archive/state/知识库，也不触发邮件。

- `--source`：当期核准阅读HTML，含 `.topic-primary`、`.report-highlights` 和 `.short-brief`。
- `--briefs`：当期简讯编选JSON，按原顺序列 `index`、`title`、`paragraphs`、`url`；编号连续，原文URL必须与源HTML逐条相等。
- `--comics`：本期竖版漫画目录，文件为 `01-手机漫画.jpg` 等，每幅先实际查看和核准。
- `--edition-json`：手机首页编选，字段见本期 `手机首页编选.json`。日期、窗口、机构数、导读和导航标题全部用当期数据，不能复制旧期事实。
- `--output-dir`：独立手机阅读版目录，与PC漫画版目录分开，保留各版本文件。

使用已核验且具备BeautifulSoup、PyMuPDF和浏览器渲染依赖的本机Python，调用 `scripts/render_mobile_weekly.py`，显式传同一业务日期。依赖缺失时停止渲染，不自行安装绕过自动化前置门。

渲染器检查正文段落、摘要、标题、元信息、列表及表格文字完整性，按实际目标页生成书签，并将浏览器命名跳转转换为显式PDF页内跳转以改善移动阅读器兼容性。输出核验JSON中的 `visual_review` 初始为pending，须在实际页面检查后更新。

## 实际验收

每期把PDF按约390像素页宽渲染查看：正文不必横移；漫画标题、标签和关键口径能读；无裁切、重叠、孤立标题或空白尾页。检查全部页面和原图，特别检查长标题、来源跨行、长段续页、每篇结尾及目录链接。结构检查不替代视觉检查。页数随内容增长，不为压页数缩小字号。

手机版与PC漫画版分别验收，分别记录实际PDF页数、书签及跳转目标、完整性检查、视觉复核和最终PDF/HTML的SHA-256；不得用手机版的通过记录替代PC版。最后按当期核准清单逐篇比较两版正文和简讯，确认条目、事实与证据完整一致，排版和分段可不同。四附件均通过后才进入邮件投递；Git备份与OneDrive同步状态按自动化运行规则另行记录。

本期2026-10-18手机阅读版为61页：6重点、23简讯、6竖版漫画；181个文字块完整，31个书签，157个有效内部链接。详见 `docs/run_receipts/2026-10-18_mobile_revision.md`。这些数字仅是本期验收结果，不能作为下期固定值。

## 2026-10-25一页导读与导航调整

手机首页编选可增加 `editorial` 对象，包含 `reviewed: true`、`stats_line`、`lead` 和 `discoveries`。每项发现含 `feature_index`（从1起，与实际重点顺序一致）、`title`、`text`；具体来源页段仍保存于当期主编选JSON。收录数量与机构数由当期完整材料计算，并复核显示值。没有此对象时保留原首页输入方式。

核准的一页首页直接接漫画与正文，完整重点导航与简讯导航在重点末尾连续排版。标题链接原文，机构和日期仍紧邻标题；页底“目录”来自实际PDF目标页。只删除和标题链接重复的篇末来源行，正文内表格与数据出处保留。HTML底部保留首页、重点和简讯入口，跳转立即完成，避免长文平滑滚动造成等待。
