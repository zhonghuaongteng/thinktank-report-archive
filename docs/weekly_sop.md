# 国际科技智库周报：每周执行规程

本规程是每周任务的唯一操作依据。旧版 Codex 任务的补丁式规则（docs/weekly_*_2026-*.md 等）不再执行，只作历史参考。

## 读者与目标

读者是从事科技政策研究的负责人。周报要让他用二十分钟知道：本周国际主要智库和官方科研机构发布了哪些值得读的研究，各自的核心结论和关键证据是什么，哪几篇值得找原文细读。

## 时间窗口

业务日期 D 为任务运行当天（北京时间）。主窗口为 D-6 至 D 共七天，以发布方网页标注日期为准。近 14 天内首发、此前未收录的重要报告可补录，正文标明原发布日期。已收录过的（state/articles.sqlite 与往期 issue 目录）不重复收。

## 选材

优先级从高到低：

1. 实质涉及明确关注议题且证据扎实：企业基础研究；AI for Science；区块链与可信协作；科研资助与科研组织新模式。
2. 六组持续问题的高质量报告：科研资助与长期资本、科产融合与成果转化、科研组织与设施平台、人才与企业创新能力、企业国际化与区域创新网络、前沿交叉研究与科学路线。
3. 本周科技政策领域影响大的报告：AI 治理与经济影响、半导体与关键技术竞争、中美科技关系、主要经济体的科技战略与预算。

不收：活动预告、播客、新闻稿转述、纯技术实验消息、一般企业经营建议。不设篇数下限，没有合格材料不凑数。单一机构重点不超过一篇。

## 成品结构

- 刊头：期号、窗口、本期篇数。
- 本周要点：三至五条，每条一句结论加一个关键数字或事实，链接到正文。
- 重点解读：三至五篇。每篇写明机构、日期、类型、原文链接；正文 1000 至 1600 字，讲清报告要回答的问题、核心结论、支撑结论的数据和案例、研究方法、原文自己承认的局限或各方分歧。有可靠数据时配一张图（内联 SVG，注明数据出处）。
- 简讯：十至十五则，按议题分组，每则 120 至 220 字，写清谁、发布了什么、主要发现或主张、关键数字。
- 官方科研机构动态：美、欧盟、英、德、法、日、韩官方科研机构本周的新战略、计划、评估，有则列，无则省略。

## 写法

- 只转述原文已有的内容。不编造场景、人物或例子，不做原文没有的推演、展望和“对我们的启示”。
- 每段至少有一项来自原文的事实、数据或明确主张；数字连同对象、时期和口径一起写。
- 区分计划与已实施、提案与已通过、作者观点与已证实结果，用主语和动词自然交代，不写免责声明。
- 术语第一次出现时用一句话解释。标题用报告原题的忠实中译，或直接陈述核心发现。
- 抓取范围、核验过程等内部记录只进 reports/weekly_runs/D/，不进正文。

## 流程与分工

| 步骤 | 执行 | 产出（reports/weekly_runs/D/） |
|---|---|---|
| 1 抓取 | 本地程序：`uv run python -m thinktank_watch.cli audit --batch 1 --limit 30 --lookback-days 14 --date D --output .../audit.csv` | audit.csv、audit.log |
| 2 机构补查 | GPT：`codex-research -f codex_sweep.md`，逐家检查重点机构与七地区官方科研机构 | codex_sweep.out |
| 3 议题雷达 | Gemini：`agy-ask <工作树> -f gemini_radar.md`，按议题全网检索 | gemini_radar.out |
| 4 合并选题 | Claude：合并三路候选、去重、核对日期，按选材规则定重点与简讯 | candidates.md、selection.md |
| 5 选题复核 | Gemini：只看候选池与选题，指出遗漏的重要报告和凑数的弱材料；Claude 逐条采纳或说明不采纳 | selection_review.out |
| 6 精读与写作 | Claude：逐篇读原文（网页或 PDF），先记要点和出处页码，再写正文 | notes/、issue.md |
| 7 事实核查 | Gemini 与 GPT 各抽查一半重点篇：对照原文核数字、归属、状态，标出空话和看不懂的句子；Claude 修改，最多一轮 | factcheck_*.out |
| 8 渲染与验收 | `uv run python scripts/weekly/render_issue.py issue.md <输出目录>`；在浏览器以手机与电脑宽度、深浅色各看一遍 | HTML |
| 9 归档与投递 | Claude：成品存 briefs/weekly/<年>/<D>/，提交并推送本分支；公众号稿用 scripts/weekly/build_wechat.py 编排后上传草稿箱并读回核对；按投递设置发送邮件 | wechat/、receipt.json |

GPT 和 Gemini 的检索结果只作线索，每条入选材料都由 Claude 打开原文核实日期与内容后才能使用。

## 来源维护

每期在 receipt.json 记录零候选与受阻来源。同一来源连续两期零候选或受阻，记入 docs/source_issues.md，由 GPT 在隔离工作树修复抓取配置，Claude 验收合并。
