具体案例可用于说明重要变化，例如AI直接改变科学问题求解、实验闭环或研发组织，或一项资助制度改变跨机构科研资源配置。是否采用取决于能否说明这些问题，不因金额大、机构知名、技术名词多或有细节就升为重点。宏观题名也不自动合格；一般地缘、政治、就业和商业评论仍须筛选。

## 一、重点文章写成能独立阅读的报告解读

1. 开头自然交代发布机构、日期、作者、报告名称和现实问题，用一段话说明报告在研究什么、主要判断是什么。必要时解释核心概念，不以未经介绍的缩写开篇。
2. 按原报告实际论证组织若干小节。通常可用两至四个有信息量的小标题，但不设固定数量，不强行套“背景—方法—启示”。标题表达具体判断或条件，例如“率先开发模型并不自动形成持久优势”，避免“技术发展与战略赋能”一类抽象标签。
3. 每个主要段落先提出具体判断，再解释依据、案例或机制，并保留足以改变结论的条件。说清谁在什么条件下做什么、为何产生这种结果。数据、案例、比较、情景和制度细节按原文实有内容展开，不要求每段都配数字或案例。
4. 区分作者主张、作者引用的他人观点、假设情景和已有事实。研究人员的实验结果、企业自报、已实施政策及尚未实施的建议不得混写。限定条件直接融入相关论述，不堆积例行免责声明。
5. 首次出现的术语用简明中文解释。保留数字的时期、对象、分母和比较基准；没有可靠数字就用有细节的机制说明，不编数，不把推测写成确定结论。
6. 深度随原报告的实质内容决定。重要报告不能仅压成三五条概括或漫画的扩写；内容简单的材料可作简讯，不拉长凑字数。摘要和漫画从完成的正文提炼；正文保存在 highlights_markdown 或独立“精华选编”，渲染不得截句或删尾。
7. 每篇就报告自身的问题、发现、论证与建议展开。保持多议题选材，不强加企业基础研究、AI4S、区块链、中国或上海关联。保留当前已确认的首页编辑导读和漫画安排。
8. 原文链接和必要来源定位保留。阅读进度、获取记录和核验过程进入内部记录；实际影响理解的局限写在相关段落中。

例如，避免只写“先发优势取决于技术扩散和组织能力”。可按用户样例的逻辑展开：报告把先发优势分成能力差距、现实运用和阻断追赶几个环节；军事运用还需要采购、训练与组织调整；模型能力扩散如果快于这些调整，率先发布模型就未必带来持久优势。这里的具体机制比抽象标签更重要。此例来自用户提供的文字，不代替下期原文核读。

## 二、全文获取不能由网页长度代替

- `detail_ok` 仅表示详情请求和提取成功；程序的 `full_text`、字符数、PDF可访问及评分都不是人工精读或覆盖整份报告的证明。
- 对窗口内、有实质研究价值的正式报告，先辨认网页是完整正文、摘要还是导论。出现“Read the full report”“Download PDF”或目录显示网页只含部分章节时，跟进其官方PDF或完整HTML，不能因网页超过5000字符跳过。
- PDF要核对题名、作者、正式发布日期和正文范围，记录具体已核读页段。可以针对选编范围精读，不冒称整份全读。只下载成功或提取出文本不能写成已核读。
- 单个来源失败按原规则跳过并继续其他来源；在逐项记录中写明链接、实际尝试、时间与错误。全文未完成和确实获取失败是两种状态。可用全文尚未核读的有价值报告必须继续处理，不能用“全文待证”作为最终排除理由。
- 付费、限制访问和无法读取的材料不得绕过访问限制。保留明确受阻记录，不把受阻写成无发布，不据摘要编造深读。

## 三、低分不能让正式报告无声消失

- 当期原始复核队列中的全部URL均须有明确去向，补充发现另列并参与同样核验；保留程序原始评分，不靠改分制造收录资格。
- P2/P3、零分及未命中关注词的正式报告同样做题意与公开摘要复核。识别AGI、artificial general intelligence、通用人工智能、superintelligence、超级智能等概念同义表达；它们是复核提示，不是自动升级或硬性收录条件。
- “paper”一词不能自动归为应排除的学术论文。应按发布栏目、用途和实际内容区分智库研究报告、政策简报、学术论文和会议论文。CNAS Reports等正式研究报告须按自身价值判断。
- 对已发现官方PDF且具有实质研究价值的报告，记录全文核读后的取舍理由。简讯数量、来源集中度正常或另一篇同机构评论已收录，都不能代替逐篇判断。

## 四、交付前检查两类遗漏

先对照完整候选队列检查有没有漏掉URL，再检查每条是否停在“待核、待证、导论已读、全文未读”。不能以已浏览标题、审阅行数或文件齐全宣称复核完成。

在当期受版本控制的 `docs/run_receipts/<D>_editorial_review.csv` 中，保留原始列并新增：

| 字段 | 填写规则 |
| --- | --- |
| 最终处置 | 重点、简讯、排除、获取受阻，四选一 |
| 取舍理由 | 具体研究价值或排除依据；不能只写低分、未命中、待证 |
| 全文状态 | 已核读、不需全文、获取受阻、未完成，四选一；正式完成不接受未完成 |
| 正文定位 | 重点与简讯均记录实际采用内容的页码、章节或段落；仅据摘要的简讯准确写摘要定位 |
| 全文获取记录 | 获取受阻时必填，写已尝试的URL、时间、结果；无实际尝试不能填受阻 |
| 写作复核 | 重点与简讯实际对照原文和阅读版后填通过，其余留空 |

重点必须已核读原文；简讯可基于核准的官方摘要且不超出其信息范围。排除可以依据明确无关的题意、材料类型或已核实的窗口外日期，不要求下载所有不相关材料；不得因为尚未读完而排除。取舍仍由实质判断负责，脚本只能检查漏项与未完成状态。

投递前用已验证Python执行仓库 `scripts/check_weekly_review.py`（自动化全局规则目录亦有副本），显式传入 `--queue <当期原始_source_health_editorial_review.csv> --review <当期最终复核.csv> --output <当期run_receipts目录下的review_check.json>`。非零退出须先补齐复核再投递。确有证据的单项获取受阻不阻断其他合格材料交付，但须在回执统计。补充候选也写入最终表。原始队列必须非空；零候选周需先在回执核实抓取失败与真实空窗，不能借空表绕过核验。

再逐篇做实质阅读检查：开头是否交代问题，主要段落是否给出具体依据或机制，术语是否解释，引用归属与条件是否准确，全文是否完整渲染。格式检查通过不等于内容质量通过。
