# 每周研究检索词的自动补充与复查

本规则用于 automation-4。企业基础研究、AI4S、区块链及既有研究问题是已确认的起点，不是封闭主题目录。每周任务可在当前授权范围内依据原文自行补充检索词、问题及探索议题，验证后更新配置，无需逐词请求用户批准。

## 每周执行

1. 读取 `config/research_interests.yaml`、研究关注说明及最近四期 `docs/interest_updates/` 记录。首先扫描本期全部来源候选的标题与公开摘要，再选择值得研究的问题精读原文。`*_source_health_editorial_review.csv` 保留所有来源在当期窗口内或首次日期待核的候选，包含低分和完全未命中项；这些记录只是发现线索，日期未核准不得归档为本周新材料。
2. 从采纳报告、值得保留的未命中报告、相邻研究领域及最近漏检记录提取新表达。寻找新同义词、组织或制度名称、问题与机制、测量方法、研究对象和新议题；不能只在三个重点周围找近义词。开放发现可以从企业需求、管理、竞争、无形投入、生产率、供应链、区域环境等问题开始，也可接受名单之外有研究价值的问题。例子不是新增配额或用户兴趣认定。
3. 对候选词核对原文中的真实含义及研究价值，再做一次针对性补查或用本期同一候选集检查其能否带来有效材料、是否造成明显误命中。导航、参考文献题名、营销标签和本批词频不能单独作为依据。不要求有价值的新发现必须多次出现；一篇扎实研究也可支持探索，但不能据此宣称它已成为用户的长期重点。
4. 按下文分类直接更新 `config/research_interests.yaml`。本轮新增词可立即用于严格七日窗口内的补查及语义复核，并在后续周次继续加载。新增词不改变原始评分，不自动提升P0/P1，不扩大日期窗口；旧材料只能提供概念背景，不能借扩词补录本周。
5. 验证 YAML 可由现有加载器读取、主题和词组没有大小写或连字符变体重复；对同一批候选比较更新前后的命中，记录有用增量和误命中。匹配变化不等于材料质量改善，需说明实际增加了什么认识。审计后修改配置时，对保存的同一批候选更新命中标记，或在当期变更记录中逐条列明差异；不能声称旧CSV已自动刷新。不为校验重复采集已经完成的材料。
6. 在 `docs/interest_updates/<D>.md` 记录本轮新增、合并、停用及保留决定，与配置和当期回执一并受控提交。没有值得新增的词时记录“无适合新增”及检查范围即可，不为每周凑词。

## 如何写入配置

- **同一概念的新表达**：补充到已有主题的 `aliases`。优先使用有辨识度的中文、英文及来源语言短语；不把语义不同但相邻的概念强并成同义词。不单独加入 research、AI、capital、growth 等过宽词来提高命中数。
- **新的研究问题或机制**：补入有关主题的 `questions`，必要时完善 `boundary`；适合词面发现时再添加准确短语。
- **确有研究价值的新议题**：新增独立主题，`level` 设为 `探索观察`，填写问题、短语和边界。可以超出既有九组，不因无法归入旧目录而排除。保留用户已确认的主题与“明确重点”属性；新议题不得自行标为用户明确指定。
- **尚未核准的猜想或词组**：只记入当期变更记录供下轮核查，不作为已验证词写入活动配置。

探索主题沿用现有 `name`、`level`、`questions`、`aliases`、`boundary` 字段。变更记录须可追溯首次加入日期和来源，不另建一个与正式配置脱节的词表。`aliases` 由程序匹配标题和摘要；`questions`、`boundary` 由每周任务模型读取并用于语义判断，匹配器本身不执行问题推理，也不自行生成新词。

## 变更记录最少内容

每次实质变更记录：词组或主题、变更类型、所属主题和层级、来源URL与原文页段、为何具有研究价值、更新前后新增命中的具体候选及误命中情况、处理决定。使用既有有效研究问题作为依据时，注明相应项目或问题出处，不从行政材料、私人通讯或文件数量推断兴趣。

四次周运行后或每月首次周运行时复查探索主题：是否带来可读的研究、是否只是噪声、是否需要拆分或合并概念。证据显示具有持续研究价值时可归入“持续关注”；不必每次审批，但须保留判断依据。持续造成误命中的词应收窄或从活动配置撤下，并将历史记录留在变更文件中。季刊、年刊或低频重要议题不能仅因几周零命中被淘汰，用户明确重点不能被自动删除。

## 开放发现的边界

该机制覆盖程序已发现的候选；入口失效、候选截断或未配置来源仍需要原有官方补查。开放队列不能被当作穷尽互联网。每周保持一次不依赖现有兴趣词的来源目录浏览和语义检查，避免已命中的材料不断强化既有词表。只有确有必要才追加来源，不能用无限扩词或扩源替代当期交付。
